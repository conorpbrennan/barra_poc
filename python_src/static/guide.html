Flex Agg ++ — dashboard guide

Barra-style factor-risk on the Soros 13F book · what each panel means and how to use it

Everything you see is computed by the Atoti cube and served through a small guarded API — the dashboard never invents a number. The top of the page carries four status strips (limits, data quality, VaR backtest, trends); every pivot view has an on-demand risk-analyst commentary button. This guide covers each.

Top-of-page status strips

🚦 Desk limits (RAG)

A red/amber/green read of the book against the desk limit set, shown on every view. It's book-level and independent of the pivot you're looking at.

  • green within limits · amber past the warn threshold · breach past the hard limit.
  • Checks: Total VaR 99, Scenario ES 97.5, Risk HHI (book-level, read against one scenario set), plus single-name and sector weight concentration.
  • All limits are upper bounds. Expand Limit detail for value vs warn vs cap and the offending name/sector.
Edit the limits

Edit limits.json at the repo root — reloaded on every check, no restart. The VaR/ES/HHI limits read against the scenario set in scenario_set (default HistFull).

🔎 Data quality

A pass/warn/fail trust check on the exact frames the cube is serving — key integrity, referential integrity, value ranges, calendar continuity, coverage. Expand for every check plus the known stubs: the demo universe is capped, Country is stubbed to "US" for all names, and a handful of names carry an "Unknown" sector. Read the risk numbers with those caveats in mind.

📊 VaR backtest (model validation)

Does the VaR actually hold up? At 99%, losses should beat VaR on ~1% of days. The backtest counts how often that happened over history, runs the Kupiec POF test, and assigns the Basel traffic-light zone.

  • The 13F book has no live daily P&L, so this is a constant-portfolio backtest: today's book applied to the daily factor-return history, rolling a window to estimate VaR each day. It validates the methodology, not a trading record.
  • The default estimator is FHS (filtered historical simulation, λ=0.94) — chosen by a sweep because it lands ~1.0% breaches (green) where plain historical sim under-covers and a normal EWMA over-breaches on the fat tail.

📈 Risk trends (2016–2024)

Risk over time, not just today: Scenario VaR 99 & ES 97.5, Risk HHI (1 / HHI ≈ the effective number of independent bets), and the top style-factor exposures. Pick the scenario set; answers "is risk rising, and where is it coming from?"

🧪 Stress test (custom & reverse)

Two modes. Custom shock — set any per-factor move in σ (standard deviations) and see the book P&L, with a per-factor contribution breakdown (P&L = Σ exposure × (σ × factor vol), the same engine as the built-in Hypo scenarios). Reverse stress — give a target loss and get, per factor, the single-factor move that would breach it, ranked by |σ| so the book's most vulnerable factor is on top (for this long-equity book that's the Market factor — it has unit beta, so it takes the smallest move).

🔀 Pre-trade / what-if

Edit the weight of any holding (0 = drop), or add a name from the coverage universe (the "add from coverage universe" picker lists every name with loadings that isn't currently held), then run. You see the book risk impact before vs after — Scenario VaR / ES, Total VaR, Specific vol, Risk HHI, and gross/net. Risk is recomputed from the same loadings, factor returns and specific variance the cube uses, so the "before" column matches the cube's reported numbers and the Δ column is the trade's effect. Trim a concentrated name and watch HHI fall; double one and watch it rise.

📉 Drawdown

The path lens VaR and ES miss. The current book is applied to the scenario set's daily factor-return history and compounded into a constant-portfolio equity curve; the panel charts that curve and the underwater (peak-to-trough) area, with the max drawdown, the peak→trough dates and the recovery. On the Soros book over full history this reads ≈ −39% — the Feb–Mar 2020 COVID crash — a path risk a single-day VaR can't show. Meaningful on long paths (HistFull, event sets); a one-shock Hypo set is too short.

💧 Liquidity (days-to-liquidate)

How long to unwind the book. Each name's days-to-liquidate = market value ÷ (participation × ADV), where ADV is its trailing-63-day dollar volume and participation is the share of ADV you'll trade per day (slider, default 20%). The panel shows the share of the book you can exit within a horizon (slider, default 5 days), the weighted-average days, the least-liquid names, and any name with no ADV (delisted / illiquid — reported separately, never counted as instant). On the Soros book at 20% participation ~87% of weight clears within 5 days, weighted-average ≈ 2.2 days, worst ≈ 13 days.

📋 What changed (quarter-over-quarter)

A deterministic diff between this 13F filing and the prior one. Three reads: positions entered / exited / resized by weight; factor-exposure drift attributed to its sources (rotation from names entering/exiting vs re-pricing from held-name loading drift — the same split as the style-drift panel); and the book risk delta (Scenario VaR / ES, Total VaR, Risk HHI, specific vol, gross/net) computed at each date with the what-if math, so it's cube-consistent. An on-demand button writes a grounded "what changed" read that leads with the biggest move and flags drift as intentional (rotation) vs not (loading drift).

Estimation-universe diagnostics

A four-phase read of the universe the model is built on and where the book sits relative to it — from Chris's (Soros risk) review. The first three live in one 🌐 Estimation universe panel; the fourth is its own.

🌐 Estimation universe — membership, funnel, span

  • Index membership (point-in-time). For each 13F filing, the book's weight split across S&P 500 (read as-of the filing date, survivorship-free) / S&P 400–600 / outside the S&P 1500 / unclassified. Answers "does the book reach names a clean large-cap universe wouldn't cover?" — on the latest filing ~20% sits outside the S&P 1500.
  • Filtration funnel. The point-in-time S&P 500 run through a documented data-quality filter stack (size, history, trading frequency, liquidity/ADV, completeness, stability buffer), tagging the first filter that drops each name. Near-flat by design — the S&P 500 is already committee-curated, so the filters confirm clean data rather than carve much away.
  • Span / high-confidence check. Is each holding inside the factor-space the estimation universe spans (high confidence) or out beyond it (extrapolation)? Measured by Mahalanobis distance from the estimation cloud, with a 2D factor-pair scatter (cloud vs book) and a per-name verdict. ~82% of the book sits inside on average, drifting out since 2021.

🧭 Style-drift attribution (intentional vs not)

The book drifted out of the S&P 500's factor space since ~2021 (into smaller, higher-vol names). Was that intentional (a deliberate tilt / new PM) or unintentional (risk re-pricing)? The panel tracks the book's net factor exposure over time and decomposes each factor's drift into rotation (new names entering / exiting) vs held-name loading drift. Rotation-dominated leans intentional → update the benchmark; loading-drift-dominated leans unintentional → update the hedge. On this book the post-2021 drift is rotation-dominated, so it leans intentional. The final call needs desk knowledge (the manager's intent); the panel lays out the evidence.

Risk-analyst commentary (per view)

Under any grid view, the 🔍 Risk-analyst commentary button writes a short risk-manager read of exactly the numbers on screen.

  • It re-runs the same guarded query the grid shows, then sends only those figures to the model. It is the plain Messages API with no tools — the model has zero access to the cube, the filesystem, or anything else, and cannot re-query.
  • It's grounded: cite the numbers, invent nothing, and lead with any limit breach.
  • On-demand only (no spend unless clicked); cached per view + slice. Try it on the saved views under Public / Soros 13F filings.

💬 Ask the risk model (scoped Q&A)

Ask a free-text question and the model answers from the live cube. Unlike the per-view commentary, this one has a tool — but exactly one: query_cube, the same guarded pivot the grid uses. So it pulls its own slices to answer, citing the numbers it queried (each query is shown inline), and can reach nothing else — no off-allowlist measure, no filesystem, no web, no second tool. The loop is bounded, so it pulls a few slices and answers. Example: "Which factor drives the most Total VaR on HistFull at the latest date?" → it queries Total VaR by factor for that date and set, then reports that Market is ~97% (the uniform unit market loading) with the style factors a rump.

The pivot

The main grid is a generic pivot over the cube: put dimensions on Rows/Columns, pick Measures, slice with the Slicers. Every number — including totals — is computed by the cube (totals are recomputed at the aggregated level, never summed from cells, because VaR is non-additive). Save a configuration as a view from the Repository panel.
